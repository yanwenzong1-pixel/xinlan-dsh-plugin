# 工作流规则摘要（脱敏版 · 可直接抄进你的 AGENTS.md）

> 这份是**给运行环境看的规则**，不是技能说明。安装完成后请把 §一～§六 精简后写进你仓库的 `AGENTS.md`（或等价的常驻规则文件），否则新环境只搬了"壳"，遇到等待/派单/重启时会退回人肉操作。

---

## 一、结构：唯一入口 + 单一调度点

```
用户 → U（用户决策，唯一入口）
     → A（待办维护，唯一派发方）
     → 执行槽位：B/F（生产）、C（发布）、E（崩溃）、G（GitHub）
执行槽位的回函 → A（不直接找用户）
A 的通知 / 摘要 / 待决问题 → U → 用户
```

- **U 只做四件事**：把用户需求原样转 A；把 A 的短通知转用户；把 A 的待决问题问用户并回传答案；其余不做。
- **U 只能派单给 A**，不得直接向执行槽位派单。
- **执行方不直接向用户提问**（含要不要重启/发布/删除）：一律写进回函「需要调度点裁决的问题」，由 A 汇总后统一问。
- 同一件活只派一个生产槽位；任务与其追加件（`-adN`）必须回同一个槽位。

## 二、派单：收据才算送达

1. 写进 `outbox/to-<槽位>-<派单号>.md` 只是"投进邮筒"；必须看到 `state/<原名>.done` 内容为 `SENT -> <槽位>`，且原件进入 `sent/`，才算已派单。
2. **同名文件只投一次**（含 `FAIL` 收据也会永久挡住同名重发）⇒ 重发换号（`-r2`）。
3. 文件名必须匹配 `to-<槽位>-<派单号>.md`，否则被静默跳过（"孤儿文件"）。
4. 目标不在线不发：先 `check` 看 `live=true`；不在线就请人打开那个会话。
5. 角色与类型必须匹配（`--kind` 硬拦）：生产=`dev/ops`、发布=`release`、行情=`data`、崩溃=`crash`、GitHub=`git`、调度=`coord`、用户入口=`user`。
6. 规格必须含「判据」与「边界」两节（脚本硬拦），判据要**可执行**（命令 + 期望输出/退出码，或 `file:line`）。
7. 问题前置：派单前把要用户裁决的问题一次问完（推荐项标「推荐」）；流程开始后不再弹新问题卡；5 分钟无回复取最推荐方案并在最终报告里列出"替你做了哪些决策"。
8. 明细可查：`relay-dispatch.mjs status` 看谁在等回函、谁已回函、谁卡住。

## 三、回合纪律①：禁止回合内 sleep 等待

- **禁止**任何工具调用里用 `Start-Sleep`（或等价手段）等待：数据刷新、回函、部署结果、下一次自然刷新。
- 需要「等待后复查」⇒ 二选一：
  - **子代理 + 后台 job**：`subagent` / `subagent_fork` / `pwsh run_in_background`；
  - **定时任务**：`schedule_create`（推荐）。
- **派发/启动监控后立即结束回合**；结果由 relay 注入或定时提醒开新回合处理。
- 派单规格里不得写"等 N 分钟后继续/回合内等待"。
- 判据：日志里搜 `Start-Sleep` 应为 0；不应出现"已回函但 A 回合仍占着"的形态。

## 四、回合纪律②：新任务默认入待办

- 用户新任务未出现「**立即 / 现在 / 马上 / 立刻就修复**」等即时指令 ⇒ **只写入待办清单**（可指派 / 待决策两节），**不派单、不追问"要不要现在派发"**。
- 只有明确即时指令才立即派发；派发后按 §三 结束回合。
- 汇报里写明本单属于「即时派发」还是「已入待办」。

## 五、重启：先看谁在跑，重启后逐个通知

- **重启前**：`check` 看在线表 + 看最近收据，判断有没有不可中断的链；有就等回函，或在通知里写清"N 分钟内收尾"。
- **重启后**：立刻给当时在跑的槽位逐个发通知，写清四条 —— ①时间与旧 PID → 新 PID + 不可用实测秒数；②你那一轮被中断了；③工作区文件不受影响；④从断点继续并在回函里说明。
- **绝不在工具调用里自己 kill 进程**；重启走标准通道并带回调。
- 冷会话**不会自动回到花名册**：回不来的槽位要请人打开窗口，再重跑 `check`。

## 六、待办清单：每次变更都要归拢重写

1. 先归拢（合并同类项、已完成移出）；
2. 归档旧版（逐字节复制到 `local/archive/`）；
3. 按简化技术写作重写（一句一意、结论在前、数字/日期/路径写全、单句 ≤25 字）；
4. 记台账（字节数、行数、指纹、搬走了什么）；
5. 跑机械门禁：`node local/tools/ste-check.mjs local/todo-list-simple.md` **exit 0**；若仓库有 HTML 门禁，重建 + 校验都要 exit 0。
6. §一/§二/§三 每条必须行首标 `【…】`（重要 / 不急 / 不用看 / 立刻处理 / 工作量大 / 被阻塞 / 缺资源），矛盾组合不许同现。
7. **派单即登记**「进行中」；收到回函同一轮改状态；验收完移出；收工前对照 `check` 的在跑列表核一遍。

## 七、最小自检（每轮回复前）

- 本回合有没有在工具调用里 sleep 等待？有 ⇒ 停止，改子代理/定时任务。
- 本回合有没有把"未写立即"的新任务直接派发？有 ⇒ 撤回为待办。
- 说"已派单"的依据是不是收据（`SENT ->`）？
- 重启相关问题：是不是经 A 汇总、并写清了 PID 与不可用秒数？
- 待办清单改了没有：归拢、标注、门禁、台账是否都做了？
