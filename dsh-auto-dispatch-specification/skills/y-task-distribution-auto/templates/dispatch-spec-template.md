## 判据

> 必须是**可执行**的验证：命令 + 期望输出/退出码；或可定位的 `file:line`。
> 不允许写"测试通过""看起来正常"。
> **两条硬要求（2026-10-04 加）**：① **证据要"看得见"** —— 检查行逐条可见 **且** 有退出码；
> 只在程序里算出布尔就报 PASS 不算证据（PowerShell 的 `(...) -and $x` 会把 `Write-Output` 的文本**捕获成非空数组**，恒为真 ⇒ 假绿）。
> ② **别写不可满足的判据** —— 对"基线本来就脏"或有常驻写者的目录（如 `release\deploy|dist|vendor`），
> 不要要求"`git diff` 为空"；改成**"相对基线快照逐字节不变"**（前后各取一次快照比字节 + 哈希）。

## 边界

- 只允许改：`<文件/目录清单>`
- 明确不做：`<不在本次范围内的东西>`
- 不许动：`<基线文件 / 生产数据 / 发布面>`
- 遇到需要扩大范围的情况：**停下来，写回函问**，不要自行扩大。
- **不许直接向用户提问**（含"要不要重启/要不要发布/要不要删"）：一律写进**回函**的「需要调度点裁决的问题」，由 A 汇总统一问用户。

- **重启**：先请求 A；**只有派单/追加件里逐字写了「本次重启已授权」才可执行**，并在回函里写明 kill 的 PID / 新起 PID / 不可用窗口实测秒数。

## 回合纪律（2026-10-28 新增 · 每单必带）

- 本单**不需要**执行方在回合内等待任何东西：**不许**用 `Start-Sleep`（或等价手段）等待数据刷新、回函、部署结果、下一次自然刷新。
- 需要「等待后复查」时，执行方二选一：**子代理 + 后台 job**（`subagent` / `pwsh run_in_background`）或**定时任务**（`schedule_create`）；
  启动监控后**立即结束回合**，由 relay 注入或定时提醒开启新回合。
- 写完回函 / 启动监控后**立即结束回合**；后续由调度点 A 在新回合处理（派单方不在回合内等回函）。
- 本单是否需要等待：`否`（默认） / `是 —— 已写明用哪种方式：<子代理|定时任务>`
- **派发口径**（派单方勾选）：`即时派发`（原话含「立即/现在/马上」） / `已入待办`（未写即时指令，仅登记待办清单）
