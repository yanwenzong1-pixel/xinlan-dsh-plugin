# 提示词：东财行情数据 · 低频抓取（不触发风控）

> 用法：把本文件**整段**作为任务提示词交给执行 Agent，替换掉「去抓东财数据」这类一句话需求。
> 本文件里的数字全部来自**服务端线上实测**（2026-09），不是保守估计 —— 它们决定这台机器还能不能继续访问东财。
> 适用：宿主侧 Node/TS（下面的原语写法以 Node 为例）；Python 侧等价替换见附录 B。

---

## 0. 你的目标，以及真正的目标函数

**要做的事**：实现「东财行情码表」抓取 + 本地落盘，供按代码或名称查 `secid`。

**真正的目标函数**：不是「把数据抓全」，而是「**不把出口 IP 抓进长期封禁**」。
东财风控的成本函数是**惩罚升级**：一旦判定为爬虫，主域持续 RST，**重启进程、换 UA、换 Referer 都不解除**。
⇒ 因此允许的失败形态是「这一轮少抓 / 早停 / 如实报未完成」；**不允许**的失败形态是「为了跑完多花一个请求」。

先记住三条铁律，下面所有规则都是它们的展开：

1. **请求预算是消耗品**：每个请求都在花这台机器有限的信誉额度，没有「再试一次不要紧」。
2. **失败要 fail-safe**：失败的正确反应是**减速或停止**；永远不是加并发、加重试、换 IP。
3. **全机一个出口**：本机**所有**东财调用（含插件里已有的行情快照等）共用**同一个**限流器 + **同一个**熔断器实例。
   各建各的出口 = 总速率翻倍 = 直接触发风控。

## 1. 接口契约（照抄参数，不要自创）

- 端点：`GET https://push2.eastmoney.com/api/qt/clist/get`；失败降级 `push2delay.eastmoney.com`（路径参数完全相同）。
- 参数：`pn=<页码,1 起>`、`pz=100`、`po=1`、`np=1`、`fltt=2`、`invt=2`、`fid=f3`、`fs=<市场过滤器>`、
  `fields=f12,f13,f14`、`ut=bd1d9ddb04089700cf9c27f6f7426281`，另加缓存杀手 `_=<Date.now()>`。
- 请求头：桌面 Chrome UA + `Referer: https://fund.eastmoney.com/` + `Accept: application/json, text/plain, */*`。
- 响应：`{ data: { total: <该 fs 总条数>, diff: [ {f12:代码, f13:市场号, f14:名称}, … ] } }`
  （`total` 只由**第 1 页**决定；`diff` 缺字段或为空都按异常处理）。
- 字段：`f12`=代码、`f13`=市场号、`f14`=名称；**`secid = "<f13>.<f12>"`**（`1.600519` / `0.300502` / `105.AAPL`）。
- 市场过滤器 `fs`（**百分号编码后发送，`+` 保留为分隔符**）：
  - 沪A（含同市场指数）`m:1+t:2,m:1+t:23,m:1+t:1`
  - 深A（含同市场指数）`m:0+t:6,m:0+t:80,m:0+t:5`
  - 北交所 `m:0+t:81+s:2048`
  - 沪深ETF `m:1+t:7,m:0+t:7`
  - 港股 `m:128+t:3,m:128+t:4,m:128+t:1,m:128+t:2`
  - 美股 `m:105,m:106,m:107`
- **明确不抓**：五档盘口（买三~五 / 卖三~五）。

## 2. 必须实现的四个原语（缺一不可）

### 2.1 全局唯一限流器（所有请求的唯一入口）
必须同时满足，且**每一条都要有单测断言**：
- **强制串行**：后一个请求必须等前一个**完成**（不是"发出"）；不允许任何形式的并发。
- **pre-sleep**：每次请求前 `sleep(uniform(2.1, 3.2) 秒)`，按 **0.1s 步进**取值（不要固定值，固定间隔本身是特征）。
- **60s 滑动窗口 ≤ 30 次**：第 31 次必须 sleep 到最旧那次请求滑出窗口为止。
- **重试的每一次尝试都要重新过限流器**：attempt #2、#3 与 #1 一样要 pre-sleep + 占窗口额度。

> 为什么这么狠：实测 **60s 窗口超过约 30 次即触发风控**。预算是算出来的：
> 1358 请求/小时（≈2.65s 平均间隔）是上限；主域必失败会让每个逻辑请求实际打 2 次，实测吞吐 **643 请求/小时（每请求 5.59s）**。

### 2.2 熔断器（含**磁盘持久化**的休眠）
- 触发：**60s 窗口内失败 ≥ 8 次** 或 **连续失败 ≥ 5 次** → 立即进入休眠，**停止一切下载请求**。
- 休眠期：**零请求**，唯一例外是每 **30 分钟 1 次**探测；探测成功才恢复，失败继续休眠。
- **休眠状态必须落盘**：新建实例（含进程重启后）加载到休眠就继续休眠。
  > 这一条专治"重启即全量重打"——重启不解封，只会把惩罚再加一级。
- 预算不受影响：熔断后预期吞吐 **857 请求/小时**（少了主域的无用重试），**不是**让你把省下的额度花掉。

### 2.3 主机轮换（固定预算 3 次尝试）
- 正常序列：`[主域, 降级域, 主域]`；熔断过之后的序列：`[降级域, 降级域, 主域]`。
- **`attempts` 预算恒为 3，不因"用了降级域"而增加**（降级不是免费额度）。
- 实测依据：主域**每请求必失败**（连接被 RST → NETWORK 类错误），而**降级域同参数成功率 100%**；
  当天整体降级率 46.9%（135/288）。

### 2.4 错误分类（决定谁计入熔断）
| 分类 | 判据 | 计入失败/熔断 |
|---|---|---|
| `NETWORK` | 连接被 RST / DNS / socket 错误 | ✅ |
| `TIMEOUT` | 单请求 **10s** 无响应（`AbortSignal.timeout(10_000)`） | ✅ |
| `PARSE` | `data` 缺失，或 `diff` 不是数组 | ✅ |
| `EMPTY_DATA` | `diff` 是**空数组**但 `total > 0` | ✅ |
| 正常空市场 | **仅当 `total === 0` 且 `diff` 为 `[]`** | ❌ |

> 为什么单列一行"正常空市场"：HTTP 200 也可能是**假成功**。把假成功当成功，等于让爬虫在"我以为很顺"的错觉里继续打满频率。

### 2.5 网络层前置
- 启动时 `dns.setDefaultResultOrder('ipv4first')` —— 实测 **IPv6 通道被 RST**。
- **绝不**把"换了 UA / Referer"当成提高并发或缩短间隔的理由（伪装头不足以通过风控，只是缺了更容易被识别）。

## 3. 分页与完整度（不能靠"某页不足 100 条"判断结束）

- 期望页数 `expected = ceil(total / 100)`，**按 expected 拉满**，不要提前结束。
- 分页会**漂移**：抓取期间行情变动会让同一代码跨页重复或整页缺失（美股实测固有缺口约 1.5%）。
- 记录已抓页码 → **缺页补齐（≤3 轮）** → 合并去重后条数仍不符 → 触发**全量重拉收敛轮（≤3 轮）**。
- **完整度阈值：`rows / total ≥ 98%` 才算本轮成功**；不达标记异常、下一轮补拉。
- 实测参照：全市场 **247 页（≈2.47 万条）**；美股 **13802 条 / 139 页**；加收敛轮后 **13778/13802（99.8%）**。

## 4. 存储与调度

1. SQLite 单文件 + **WAL**；表
   `securities(market TEXT, code TEXT, name TEXT, secid TEXT, market_num INTEGER, PRIMARY KEY(market, code))`，
   另建 `code`、`name` 两个索引。
2. **整市场替换 + 幂等**：每个市场在**一个事务**内 `DELETE` 旧行 + `INSERT OR REPLACE` 新行
   （崩溃不留半市场数据；重复执行不产生重复数据）。
3. **完整度校验**：写完断言 `COUNT(*)` 与接口 `total` 一致（≥98%）；
   **不得用不完整数据覆盖上一轮的完整数据**。
4. 调度：默认**每 8 小时一轮** + **每天 09:00 强制一轮**；单实例互斥；**按页断点续拉**
   （进度落盘，中断从缺失页继续，**禁止整表从头重拉**）。
5. 抓取失败 / 熔断休眠**不得影响插件其它功能**（查询一律走本地库）。

## 5. 明确禁止（违反即返工）

1. **不绕过限流**：不并发、不多进程/多实例、不改下限、不动窗口。
2. **不把降级/重试/补页/收敛当成提高请求总量的理由**（`attempts` 预算恒 3）。
3. **熔断休眠期内不发任何东财请求**（除 30 分钟 1 次探测）。
4. **不把 `200 + 空 diff` 当成功**（除 `total=0`）。
5. **不抓五档盘口**。
6. **不从浏览器/前端直连东财**（CORS + 风控双拦，还会暴露用户 IP）——必须宿主侧单出口。
7. **不与其它东财调用各建出口**：全机共用**一个**限流器 + **一个**熔断器。
8. **不用不完整的一轮覆盖完整数据**。
9. **不得只交单测**：必须给**真机实测数字**。

### 5.1 如果你发现自己正在这样想，立刻停下
| 这个念头 | 事实 |
|---|---|
| "就多试这一次" | 每次尝试都占 60s 窗口额度，都要 pre-sleep —— 没有"顺便"的请求 |
| "这两页可以并发发" | 串行是硬约束；并发是被识别的最快路径 |
| "降级域很快，可以多加几页" | 降级不是免费额度；预算恒 3 次尝试、窗口恒 30 次 |
| "换个 UA / 换个库再来一遍" | 惩罚跨重启，换 UA 不解除；主域 RST 是**按出口 IP**判定的 |
| "重启一下熔断就清了" | 休眠状态已落盘，重启后**仍然休眠**（这是设计，不是 bug） |
| "先把数据抓下来，限流回头再补" | 反了：限流是前提，不是优化项 |

## 6. 测试要求（TDD：**先红后绿，禁止跳过**；用注入的假时钟 + 假 fetch，**不联网**）

限流 · 重试 · 主机轮换 · 熔断 · 熔断持久化 · 解析 · 分页 · 存储 · 边界异常

1. **限流**：串行断言（并发调用时校验**实际发出顺序与间隔**）；pre-sleep 落在 `[2.1, 3.2]` 秒；窗口第 31 次被推迟。
2. **重试也过限流**：断言 attempt 之间**也有**间隔。
3. **主机轮换**：主域 `NETWORK` 失败 → 下次用降级域；**总尝试数恒为 3**（不因降级变 4）。
4. **熔断**：窗口 8 次 / 连续 5 次失败 → 休眠（休眠期断言**零**请求）；30 分钟后 1 次探测；成功恢复、失败继续休眠。
5. **熔断持久化**：写文件后**新实例**加载仍休眠。
6. **解析**：`data` 缺失→`PARSE`；`diff:[] 且 total>0`→`EMPTY_DATA`；`diff:[] 且 total=0`→正常空市场。
7. **分页**：按 `ceil(total/100)` 拉满；单页失败只补该页；条数不符触发收敛轮；`pz` 恒 100。
8. **存储**：整市场替换幂等；事务性（中途抛错不留半市场）。
9. **边界异常**：`total` 缺失/为 0/远大于实际；页码超上限（防死循环）；名称含逗号引号中文；
   代码含前导零（**按字符串处理，不得被 `Number` 化**）。

## 附录 A · 同机旁证（Python 侧实测，2026-08-31，`test/scrape/README.md`）

与上面服务端结论一致的独立证据，供理解"为什么"：

- **curl_cffi（浏览器指纹客户端）5/5 通；requests（普通指纹）0/6 全挂（`RemoteDisconnected`）**
  ⇒ 除速率外，**TLS 指纹也是变量之一**。但**不要**把"换库/换 UA"当解法：Node 侧你改不动 TLS 指纹，
  所以能走的路只有两条 —— **降级域 + 严格限流**。
- **本机 requests 默认命中系统代理（`127.0.0.1:7078`）产生 `ProxyError` 噪音** ⇒ 对照或直连时要显式 `trust_env=False`。
- **A 记录轮换（当日出现 `101.226.30.206 / .136 / 14.103.191.91`）** ⇒ 不是稳定的 IP ACL，而是**指纹敏感 + 频率敏感的间歇性 WAF**。
- **间隔 < 1s 快速连打会触发风控**（同刻交替测试第 3 次成功后连续 RST，`curl error 56`）；**间隔 2s 可持续成功 5 次**
  ⇒ 与 §2.1 的 `uniform(2.1, 3.2)` 下限互相印证。
- **本机 IPv6 到东财是路由黑洞**（curl CLI 默认解析 IPv6 直接失败，curl_cffi/requests 走 IPv4 正常）
  ⇒ 与 §2.5 的 `ipv4first` 同一现象。
- **回退通道**：`push2delay`（当日全通道可通）、`searchapi`（稳定）、`push2his`（当日 1/3，需重试）。

## 附录 B · 换语言时的等价原语

| 原语 | Node / TS | Python |
|---|---|---|
| 强制 IPv4 | `dns.setDefaultResultOrder('ipv4first')` | 自建 `HTTPAdapter`/`socket` 只取 `AF_INET`；或在 `getaddrinfo` 上过滤 |
| 单请求超时 | `AbortSignal.timeout(10_000)` | `timeout=(5, 8)`（连接/读取分开） |
| pre-sleep | `await sleep(uniform(2.1, 3.2))` | `time.sleep(random.uniform(2.1, 3.2))` |
| 串行 | 单一 promise 链 / 互斥锁队列 | 单一 `threading.Lock` + 单 worker 线程（不要用 `asyncio.gather`） |
| 熔断持久化 | 写 JSON 文件（含 `sleepUntil`） | 同左（写文件或 SQLite 一行） |
| 别用 | 多 worker / `Promise.all` | 多进程 / `ThreadPoolExecutor` |
