## 5. 抓取方法（实现约定）

1. **FRED**：一次 HTTP GET 拼上全部 ID；超时 20 s；失败重试 2 次（指数退避 2 s / 5 s）；结果写临时 CSV 后解析（`observation_date` 为列名，空值 `''` → 跳过该格）。
2. **akshare**：逐函数调用，**串行**；相邻调用 `sleep 1~2 s`；每个函数调用包一层 try/except，失败只记 log 不影响其它项；调用时临时屏蔽 tqdm 进度条输出（`bond_zh_us_rate` 会打印 19 行进度）。
3. **统一后处理**：日期→`YYYY-MM`（月频）或 `YYYY-MM-DD`（日频）；数值→float（去千分位、去 `%`、`nan` 视为缺失）；列名→内部 `series_key`（见 §7.2）。
4. **网络**：仅用 HTTPS；**不设置代理**（见 §8）；UA 用常规浏览器 UA，避免被上游判为异常客户端。
5. **日志**：每次运行写一行到 `fetch_log`（`run_at, source, series_key, rows, status, error`），并在 stdout 打印一行汇总（成功项数/失败项数/各源耗时）。

## 6. 更新方式（增量语义）

| 规则 | 内容 |
|---|---|
| **写入语义** | `INSERT … ON CONFLICT(series_key, period) DO UPDATE SET value=excluded.value, fetched_at=excluded.fetched_at`（upsert 覆盖） |
| **增量范围** | 每次只处理**最近 6 个月**的数据点；更早的历史**不动**（既省流量也避免误伤） |
| **窗口淘汰** | 保留最近 **36 个月**：写入结束后删除 `period < 本月−35 个月` 的行（按 `series_key` 各自计算） |
| **修订处理** | 覆盖式写入天然吸收修订（同一 `period` 被新值替换）；另在 `value_prev` 列保留上一版值，便于发现修订幅度 |
| **幂等性** | 同一天重复运行结果一致（upsert + 删除窗口外），可安全重跑 |
| **失败降级** | 某序列本次抓取失败 → **不删除旧值、不写空值**，仅记 `fetch_log.status=failed`，页面/下游继续用上次成功值（并在数据里带 `stale_days`） |
| **日频 vs 月频** | 日频序列按日存（6 个月 ≈ 130 行/序列），另建视图 `v_month_end` 取"每月最后一个交易日"供月度展示；月频序列按 `YYYY-MM` 存 |
| **每日增量成本** | 13 项 × 6 个月 ≈ 月度类 <100 行 + 日频类 ≈ 4 序列 × 130 行 ≈ 520 行 ⇒ **每天写入 <1,000 行**，可忽略 |

## 7. 存储设计（建议：SQLite 单文件即可，无需 DuckDB/服务端）

### 7.1 表结构（草案）

```sql
-- 主表：一条序列一个数据点
CREATE TABLE IF NOT EXISTS macro_series (
  series_key  TEXT NOT NULL,      -- 内部标识，见 §7.2
  period      TEXT NOT NULL,      -- 月频 'YYYY-MM'；日频 'YYYY-MM-DD'
  value       REAL,               -- 数值（缺失为 NULL）
  value_prev  REAL,               -- 上一次写入值（用于观察修订）
  unit        TEXT,               -- 'percent' | 'index' | '100_million_yuan' | 'billion_usd' | 'thousand_persons'
  source      TEXT NOT NULL,      -- 'FRED' | 'akshare'
  source_id   TEXT NOT NULL,      -- 'DGS10' | 'macro_china_cpi' …
  freq        TEXT NOT NULL,      -- 'D' | 'M'
  fetched_at  TEXT NOT NULL,      -- ISO8601 本机时间
  note        TEXT,               -- 口径备注（如 'SA' / '官方PMI' / '东财口径'）
  PRIMARY KEY (series_key, period)
);
CREATE INDEX IF NOT EXISTS idx_macro_period ON macro_series(period);

-- 运行日志
CREATE TABLE IF NOT EXISTS fetch_log (
  run_at     TEXT NOT NULL,
  source     TEXT NOT NULL,
  series_key TEXT NOT NULL,
  rows       INTEGER,
  status     TEXT NOT NULL,       -- 'ok' | 'failed' | 'partial'
  error      TEXT
);

-- 月末视图（供月度展示/导出）
CREATE VIEW IF NOT EXISTS v_month_end AS
SELECT series_key, substr(period,1,7) AS ym, value, unit, source
FROM macro_series
WHERE freq = 'D'
  AND period = (SELECT MAX(period) FROM macro_series m2
                WHERE m2.series_key = macro_series.series_key
                  AND substr(m2.period,1,7) = substr(macro_series.period,1,7));
```

### 7.2 `series_key` 命名规范（建议）

`<国家>-<指标>-<口径>`，全小写连字符，例：

```
cn-cpi-yoy            # 中国 CPI 同比（%）
cn-pmi-mfg            # 中国制造业 PMI（指数）
cn-m2-balance         # 中国 M2 余额（亿元）
cn-m2-yoy             # 中国 M2 同比（%）
cn-ust10y / cn-ust30y # 中国国债 10Y / 30Y（%）
us-cpi-index          # 美国 CPI 指数（CPIAUCSL）
us-cpi-yoy            # 美国 CPI 同比（自算）
us-pce-index          # 美国 PCE 指数（PCEPI）
us-pce-yoy            # 美国 PCE 同比（自算）
us-pmi-mfg            # 美国制造业 PMI（ISM）
us-m2                 # 美国 M2（M2SL，十亿美元）
us-ust10y / us-ust30y # 美国国债 10Y / 30Y（%）
us-fed-target-upper   # 美联储目标区间上限
us-fed-effr           # 有效联邦基金利率
us-nfp-change         # 美国非农新增（千人，差分）
```

### 7.3 体量与备份

36 个月全量：月频约 10 序列 × 36 行 ≈ 360 行；日频 4 序列 × 780 行 ≈ 3,120 行 ⇒ **全库 < 4,000 行、< 1 MB**。建议：每日运行后把 SQLite 文件纳入你现有的备份/版本管理流程（或导出 CSV 归档）。

| `www.chinabond.com.cn`（中债，备用） | HTTP 200 / 2746 ms | ✅ 可达（偏慢） |
| `www.bls.gov` | **HTTP 403** | ⚠️ 官网直抓被拒（**本方案不经 BLS 官网**，美国 CPI 走 FRED，故无影响） |
| `tradingeconomics.com` | HTTP 200 / 1184 ms | 备用（PMI 缺口时的候选） |

**结论：本方案不需要海外代理。** 唯一需要留意的降级路径：若某天 FRED 不可达，美国侧可临时改用 DBnomics（`api.db.nomics.world`）兜底 —— 但注意 **DBnomics 没有 `DGS10/DGS30`**，10Y/30Y 只能用 `FED/NOMINAL_YIELD_CURVE/SVENPY10`（模型拟合，实测 1961→2026-10-02）近似，**并必须在数据里标注口径降级**。

## 9. 口径与坑（逐项必读）

1. **CPI/PCE 是"指数"，同比要自算**：FRED 的 `CPIAUCSL`/`PCEPI` 是指数值；`us-cpi-yoy` = `index_t / index_{t-12} − 1`。若想省事可用 akshare 现成同比（`macro_usa_cpi_yoy` 实测到 2026-09，但当月常为 `nan`），代价是口径黑箱。
2. **中国 CPI 的两套列**：`macro_china_cpi` 同时给「当月指数(100.8)」「同比增长(0.8%)」「环比增长(0.4%)」——**别把 100.8 当同比**。
3. **PMI 两套口径**：中国用 **统计局官方**（`macro_china_pmi`，50.1）；**财新 PMI 是另一口径**（本方案不取）。美国 ISM 与 S&P Global 亦不同口径，库里必须写 `note`。
4. **M2 口径**：中国 `macro_china_money_supply` 给"数量(亿元)/同比/环比"；美国 `M2SL` 是**十亿美元、季调**。两者**不可直接比大小**，跨市场比较要用同比或占 GDP 比。
5. **中美利差要先做交叉校验**：中国 10Y 来自东财口径（`bond_zh_us_rate`），美国 10Y 主用 Treasury 官方（`DGS10`）。建议前 3 个月用 `bond_zh_us_rate` 的「美国国债收益率10年」列与 `DGS10` 重叠比对，偏差 >5bp 就在数据里标注。
6. **非农新增是差分，且会被修订**：`PAYEMS` 是水平值（千人），新增 = 本月−上月；因修订频繁，**必须依赖 6 个月覆盖式增量**（只追加最新月会永久留下旧口径的历史）。
7. **`macro_china_money_supply` / `macro_china_cpi` 是倒序表**：入库前按日期升序排序（这是本次实测踩到的坑）。
8. **akshare 日历类接口不可信**：所有带「今值/预测值/前值」三列的"财经日历"接口实测普遍滞后约 1 年 —— **本方案已把这类接口全部排除**。
9. **FRED 月度日期是"月初"**：`2026-08-01` 表示 2026 年 8 月；统一转 `YYYY-MM` 后再入库。
10. **缺失值语义**：FRED CSV 用空字符串；akshare 用 `nan`/空串。统一为 `NULL` 并跳过写入（**不要写 0**）。

## 11. 验收判据（开发完成时逐条核对）

1. 13 项指标的 `series_key` 全部存在，且每项 **≥36 个周期**（日频 ≥700 行）。
2. 抽样 3 项（`us-cpi-index`、`cn-pmi-mfg`、`us-ust10y`）与官方页面/FRED 网页**逐值一致**。
3. 连续跑两次，第二次 `rows` 变化 ≤ 每日新增量，且**库内无重复 (series_key, period)**。
4. 故意断开 FRED（改错 URL）→ 中国 9 项**不受影响**，`fetch_log` 记 8 条 failed，旧值仍在。
5. 6 个月窗口外（例如 8 个月前）的历史值在本次运行后**未被改动**（用 `value_prev` 与 `value` 比对）。
6. 窗口淘汰生效：人为插入一条 40 个月前的记录，运行后被清除。
7. 单次运行总耗时 < 60 s（实测预估：FRED 2 s + akshare 约 10 s + 处理 <1 s）。
