# dsh-quick-append v0.5.2 —— 「预存命令」浮层装得下、够得着（2026-10-04）

> 触发：用户现场截图 —— 预存 **7 条**命令，上拉菜单只显示 **6 条**，第 7 条看不到；
> 菜单右上角计数写着「7 条」，与实际可见条数不符。
> 本轮**只修可见性/可达性**，不改业务语义（插入、增删改、隔离、快捷键都不动）。
>
> **第一部分：左键上拉菜单**（症状如上）。
> **第二部分：编辑弹窗**（右键入口，同一缺陷类：底部操作行被推出弹窗可视区）——见文末「第二部分」。

## 0. 症状与现场判据

| 项 | 现场 |
|---|---|
| 用户可见 | 菜单显示 6 条，第 7 条看不到；底部的「左键插入正文 · 右键录入/编辑」提示行也不见了 |
| 计数 | 头部计数「7 条」正确（数据没问题，是**渲染**问题） |
| 环境 | dev 3080，Chromium（Playwright），1280×900 与 625×613 两种窗口都复现 |

## 1. 根因（真机实测，非推断）

一次性探针（`%TEMP%\qa-menu-geom.mjs`）直接量浏览器算出来的几何，结果：

| 条数 | 面板 clientH | 面板 scrollH | 列表 clientH/scrollH | 列表底边 vs 面板底边 | foot 在卡片内 | 最后一条在卡片内 |
|---|---|---|---|---|---|---|
| 4 | 228 | 228 | 134 / 134 | −52 | ✅ | ✅ |
| **7** | **258** | **324** | **236 / 236** | **+20** | ❌ | ❌ |
| 20 | 258 | 328 | 240 / 358 | +24 | ❌ | ❌ |

三件事同时成立，才是"看不到"的完整成因：

1. **预算不够**：面板内联 `max-height: 260`，而内容需要 324（头部 31 + 列表 236 + foot 39 + 间距 12 + 内边距 12）；
2. **越界的是"列表底部"而不是"列表内部"**：列表底边比面板底边低 20px ⇒ 最后一行被画在**卡片矩形之外**，
   而卡片当时 `overflow: visible`，于是那一行直接落到宿主 UI 的地盘上、被宿主元素盖住；
   foot 整体被挤出卡片（`footVisible:false`，与截图里提示行消失一致）；
3. **连"滚动"这条退路也没有**：列表是 flex 列容器，7 个条目被**压扁**塞进 236px
   （`scrollHeight == clientHeight`，实测 0 可滚余量）⇒ 用户滚不动，也没有滚动条（规范要求隐藏）。

**为什么门禁没拦住**：既有真机 F21 只断言 `list.scrollHeight > list.clientHeight`（"能滚"）、
`listH <= 240`、`panelH <= 320` —— 三条在故障态下**全部成立**（20 条时列表确实是 240/358 能滚、
面板 260 ≤ 320）。它从未断言「最后一条落在卡片矩形内」或「foot 可见」，所以是**结构性假绿**。

## 3. 验收场景（业务可见）

1. 预存 7 条 → 打开菜单：**7 条全部可见**，底部提示行在，不需要滚动；
2. 预存 20 条 → 菜单显示到预算上限，**列表可滚**、滚到底能看到并点到第 20 条，底部提示行仍在，
   且提示行右侧出现「滚动查看更多」（滚动条按规范是隐藏的，必须另有文字提示）；
3. 窗口很矮（900×300）→ 面板高度夹紧到视口内，**不越过屏幕边**，foot 仍可见、最后一条仍可点；
4. 4 条（装得下）→ **不出现**"滚动查看更多"（反例，防止提示变成噪音）；
5. 其它交互零回归：点条目插入正文、右键弹窗、互斥、Esc、resize/scroll 关闭、长短标题截断等（F1–F24 全绿）。

## 5. 真机门禁（60 → 64 项）

新增/重写的判据一律**不看 `scrollHeight` 猜**，而是：

- `panel.scrollHeight <= panel.clientHeight + 1`（卡片装得下自己的内容）
- head / foot / 最后一条的 **`getBoundingClientRect()` 落在面板矩形内**
- 最后一条中心点 `document.elementFromPoint()` **命中它自己**（真能点到，不是"数学上存在"）

| 例 | 场景 | 判据要点 |
|---|---|---|
| F21（重写） | 20 条 | 列表可滚 + 面板不溢出 + head/foot/最后一条都在卡片内 + 出现溢出提示 |
| F25（新） | **7 条（用户现场）** | 面板不溢出、**列表无需滚动**、foot 可见、第 7 条在卡片内且可点 |
| F25b（新） | 7 条 | **不出现**溢出提示（反例） |
| F26（新） | 20 条 | 溢出提示出现；滚到底后第 20 条仍在卡片内可点 |
| F27（新） | 900×300 + 20 条 | 面板高度 ≤ 视口 − 10px；foot 不被挤出；最后一条仍可点 |

**本机实测**：`✅ 64/64 通过`（修复前 60/64）。

## 8. 风险清单（如实登记）

1. **预算 344 是"按当前行高"算的**：条目字号/内边距若将来改动，`COMMAND_MENU_ROW_PX=34` 与
   `COMMAND_MENU_CHROME_PX=94` 必须同步 —— 真机 F25（7 条不滚动）会先红，这是**有意的护栏**。
2. **溢出提示依赖一次渲染后实测**：菜单打开当帧为 `false`，下一帧才可能变 `true`（实测无可见闪烁，
   因为菜单本身也是同一帧出现）。若将来菜单改为常驻显示，需要重新评估测量时机。
3. **矮视口下的下限 140px**：视口极矮（< 150px）时面板仍取 140，此时可见区只剩 1 行左右
   （头部与 foot 有 `flex:none` 保护，不会被挤掉，但列表可点区域很小）。
4. **`max-height: 240px` 契约作废是行为变更**：若有外部脚本/文档按该值断言，会失效（本仓内已同步）。
5. **未覆盖**：macOS/Linux 浏览器未实测（本项目历来只在 Windows + Chromium 真机验证）；
   Firefox/Safari 的 flex + `min-height:0` 表现未验证。
6. **环境变量缺省行为**：`DSH_CHECKOUT` 未设置时那条跨仓契约用例会 skip ⇒
   在 CI 里"240 例全绿"实际是"239 通过 + 1 跳过"，报告必须写明（本文件与 README 均已写明）。

# 第二部分：编辑弹窗（同一缺陷类，2026-10-04 第二轮）

> 目标轮要求"同类弹窗列表需评估影响面并统一修复"。左键菜单修完后，按同一套几何判据复查
> **右键进入的编辑弹窗**，确认它存在**同一类**缺陷（滚动落在错误的容器上 ⇒ 底部操作行被推出可视区）。

## 10. 实测临界值（先量后改）

真机探针（Playwright，1000 宽，n 为命令条数，逐格扫视口高）：

| 现象 | 实测临界 |
|---|---|
| 列表开始内部滚动 | **N₁ = 4 条**（3 条时列表 133px 不滚；4 条时内容 178px > 上限 150px ⇒ 列表滚动） |
| 弹窗**整体**开始滚动（滚动落在错误容器上） | **视口高 ≤ 530px**（弹窗内容固定 457px，而 `max-height = min(86vh, 460px)`） |
| 底部操作行被推出弹窗可视区（`footInside=false`） | **视口高 ≤ 500px** |
| 底部按钮**点不到**（`elementFromPoint` 命中不到它） | **视口高 ≤ 460px** |

对照：视口高 1000px（常见桌面）时**不失败** —— 因为列表 150px 封顶把增量吃掉了。
所以这个缺陷的真实触发条件是「**条数 ≥ 4 且视口高 ≤ ~534px**」，而不是"条数越多越溢出"。
（"条数越多越溢出"是**第一部分菜单**的形态：菜单没有列表层封顶，7 条即溢出卡片。）

## 11. 根因（分层定位）

| 层 | 旧行为 | 问题 |
|---|---|---|
| 弹窗容器 `.dsh-qa-dialog` | `overflow-y: auto`，`max-height: min(86vh, 460px)` | 可见高度不足时**整窗**成为滚动容器 —— 滚动条出现在错误的容器上 |
| 弹窗内容区 `.dsh-qa-body` | 普通 block，无高度约束 | 不参与收缩，无法承担滚动 |
| 列表容器 `.dsh-qa-cmd-list` | `max-height: 150px` 写死 | 把"超出部分"转嫁给整窗滚动，而不是让自身按剩余空间伸缩 |
| 底部操作行 `.dsh-qa-dialog .dsh-qa-footer` | 位于滚动流内、无 `flex` 约束 | 被推到内容末尾 ⇒ 出可视区、点不到 |

一句话：**不是"列表无限撑高"，而是"卡片没装下内容、滚动落错层、底部操作行随流被推走"。**

## 12. 修复（改在正确的层）

| 位置 | 改动 |
|---|---|
| `.dsh-qa-dialog` | += `display:flex; flex-direction:column; overflow:hidden`；**去掉** `overflow-y:auto`（不再整窗滚）与失效的隐藏滚动条声明 |
| `.dsh-qa-body` | += `flex:1 1 auto; min-height:0; overflow-y:auto; overscroll-behavior:contain` + 隐藏滚动条 ⇒ **安全阀**：正常不滚，只有"表单 + 列表最小高度"都塞不下时才滚 |
| `.dsh-qa-cmd-list` | **删掉 `max-height:150px`**；+= `flex:1 1 auto; min-height:44px`（恰好一行）⇒ **首选滚动区** |
| `.dsh-qa-cmd-row` | += `flex:none`（条数多时是滚动，不是把行压扁） |
| `.dsh-qa-head` / `.dsh-qa-form` / `.dsh-qa-dialog .dsh-qa-footer` | += `flex:none`（固定底座，空间不足时先让列表缩） |
