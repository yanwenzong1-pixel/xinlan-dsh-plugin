## 2. 业务关键验收场景

1. **跨工作区不串**：工作区 A 设「AAA」→ 切到工作区 B → B 读到的是**它自己的值**（没设过就是空），A 的值不受影响。
2. **跨刷新/重启保留**：设好值后刷新页面（或重启宿主）→ 每个工作区的值都还在。
3. **新建工作区为空**：本地没有该工作区条目时读到空串；首次追加**不会**带上任何其它工作区的文案（会提示去设置）。
4. **快速切换 + 连续编辑不串写/不丢**：编辑期切换工作区，写入仍落在**打开弹窗时**那个工作区；连续保存由合并窗口合并为一次落盘。
5. **写失败有可见反馈 + 内存态降级**：存储不可用/配额超限时给出「追加文案保存失败：…（当前页面内仍可继续使用，刷新后会丢失）」，且这一笔编辑**在本页仍然可用**（真机 E12 / E12b / E12c 逐条验）。
6. **旧配置不丢**：升级后第一次打开，旧版全局文案迁到**当前**工作区并删除旧键；其它工作区仍是空。
7. **同名工作区不混**：两个工作区展示名相同也各自独立（键是 ID）。
8. **重命名不动配置**：工作区改名后配置仍跟随（键不变）。

## 6. 风险清单（含尚未由机器覆盖项）

1. **无工作区归属的会话**落 `__no-workspace__` 占位桶，彼此共享一份文案。理由：这类会话没有工作区可绑定，共享一个桶比"读不到/报错"可用。**未真机验证**（当前实例里会话都归属工作区）。
2. **工作区删除后配置保留、不自动清理**（需求允许"保留"策略）。理由：列表未就绪（`phase === 'pending'`）时误判删除会**永久丢配置**；工作区可能被重建（同 ID 恢复即配置回填）；每条只有几十字节。代价：长期使用可能留孤儿条目 —— 真要清理建议做成**显式用户动作**，不做自动清理。
3. **真机上没走"UI 切换工作区"**：切换会调 `connectWorkspace()`，目标工作区没有空会话时会**新建一个会话**（`navigation.ts:121-130`），那会写进用户实例。故真机用"向存储种入第二个工作区 + 刷新"来验证隔离与"新建为空"（E8/E10），**UI 切换本身未在真机走过** —— 由 §5 人工步骤 1 覆盖。
4. **真机未开两个标签页**：多标签同步（`storage` 事件）只有单测与接线层覆盖。
5. **合并窗口 250ms**：保存后约 250ms 才真正落盘；期间强杀浏览器**可能**丢这一次（缓解：`pagehide`/`visibilitychange`/切换/卸载四处 flush）。未做"强杀进程"实测。
6. **两个全局开关仍全局**：「LLM优化」「goal模式」照旧单键（`dsh-quick-append.llm/.goal`）—— 需求只要求追加文案按工作区隔离。若要一并隔离，需扩结构（**未做**）。
7. **既有缺陷未修（不在本轮范围）**：`appendWithLlm` 里 `cwd` 取自 `workspaces?.recentWorkspaceId`，该字段在框架里不存在 ⇒ `cwd` 恒为 `''`（提示词优化拿不到项目路径）。已在 §0 记录；改动它属宿主契约面，本轮不动。
8. **存储体积无上限**：超长文案（15000 字符级）已测不截断，但若用户给很多工作区各存极长文案，理论上可能触发 localStorage 配额 —— 那时会走"失败可见反馈"路径（不静默），但**没有主动的容量保护**。
