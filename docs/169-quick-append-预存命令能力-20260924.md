**三处需要用户知情的取舍**（都是需求没写死、由现状倒逼的决定）：

1. **"插入"= 追加，不覆盖**：草稿为空 → 只放正文；草稿非空 → `草稿 + 空行 + 正文`。理由：需求 3.3 说的是"插入"，而覆盖会毁掉用户已经写了一半的需求（不可撤销）；且与「点击追加」的拼接口径一致。
2. **保存后表单复位为"新增"态**：新增/修改保存成功后清空表单并退出编辑态 —— 状态可预测（需求 6.2），不会出现"看着像在改 A，其实点下去又新增一条"。
3. **弹窗是"居中模态"，菜单是"按钮上方上拉"**：需求 3.1 明确要求菜单向上拉起并锚定按钮；需求 4.5 又要求编辑弹窗有遮罩（模态语义）⇒ 弹窗用遮罩 + 居中定位（面板比按钮大得多，锚定到 26px 按钮上没有意义），但**卡面/按钮/输入框/标题/ footer 全部复用既有类**，视觉不割裂。

## 2. 业务关键验收场景

1. **位置与外观**：预存命令按钮在「点击追加」左侧 **5px**，只有扳手图标（无文字），26×26 / 圆角 8 / 1px 边框 / 透明底 / 同字色 —— 与「点击追加」逐项一致（真机 F2/F2b/F3/F3b 逐项比对 computed style）。
2. **有数据左键**：菜单在按钮**正上方 5px**、右缘对齐、整体在视口内；列表渲染标题，过长省略号截断并保留完整 `title`，超长内部滚动（F8b/F9/F9c）。
3. **无数据左键**：**不出现空菜单**，弹出「暂无预存命令，右键『预存命令』可录入指令」（F4/F4b）。
4. **选中即插入**：正文被写入输入区（逐字含换行），菜单关闭，输入区保持聚焦，光标在插入文本末尾，**不自动发送**（F10/F10b/F10c/F10d）。
5. **右键录入闭环**：右键打开弹窗 → 新增 → 保存 → 左键菜单**立即**出现该条 → 刷新后仍在 → 修改 → 删除（二次确认）（F5/F7/F8b/F13/F14/F15/F17）。
6. **校验**：标题/正文 trim 后必填；标题 >50 或正文 >2000 给出带字数的提示且**不写入**（F6/F6b）。
7. **未保存变更**：点关闭/Esc/遮罩 → 先问「确定放弃？」；「继续编辑」保留内容，「放弃」关闭且磁盘不变（F16/F16b/F16c）。

12. **长列表与超长标题**：20 条时菜单**内部滚动**（列表高度被 `max-height` 限住、20 项都在、面板不撑破）；标题过长**省略号截断**且完整标题仍可从 `title` 属性取回（F21/F22）。
13. **健壮性**：快速连点**不叠加浮层**（最多一个菜单）；短视口（900×300）下**限位生效** —— 面板坐标非负且不越出视口（F23/F24）。

## 5. 手工验收步骤（真机脚本已覆盖，人工复看用）

1. 刷新 dev 3080（Ctrl+F5）。composer 右侧应看到 **两个** 图标按钮：左扳手、右闪电，间距 5px。
2. 左键扳手：**首次**（无数据）应弹「暂无预存命令，右键『预存命令』可录入指令」，不出现空面板。
3. 右键扳手：弹窗居中、有遮罩；标题留空点「新增」→ 红条提示「标题不能为空」。
4. 填标题 + 两行正文 → 「新增」→ 关弹窗 → 左键扳手 → 面板在按钮正上方，点该条 → 正文进输入区且光标在末尾。
5. 刷新页面 → 左键扳手，条目仍在。
6. 右键 → 「编辑」改标题 → 「保存修改」；「删除」点两下（第一下变「确认删除」）。
7. 改点内容后点「关闭」→ 出现「有未保存的修改，确定放弃？」；「继续编辑」应保留内容。
8. 右键闪电按钮：「快捷追加文案」弹窗应与预存命令的浮层互斥（不会同时出现）。

## 6. 风险清单

1. **"用户维度隔离"只到浏览器画像**：客户端拿不到宿主身份（且不得触碰鉴权，铁律 46），同一浏览器画像被多个用户共用时预存命令**互相可见**。若将来需要真正的按账号隔离，必须走宿主侧存储（Host 改动 + 重启），属独立一轮。
2. **跨插件层级**：本插件局部队列是 `100/110/111`，远低于本仓其它插件浮层的 `2147483020+`。**跨插件遮挡**（被别的插件 dock/菜单盖住）本轮未处理也无判据 —— 需求只要求"高于输入区与既有菜单"，已满足。
3. **弹窗未做焦点陷阱（Tab 循环）**：需求 7.3 只要求"可 Tab 聚焦"，已满足；但 Tab 可以走到遮罩后面的页面元素（遮罩会拦住鼠标，不拦键盘）。未实现的原因是本仓其它插件用的是各自的 trap 实现，引进来会与遮罩语义重复；列入待办。
4. **无 i18n / 主题切换适配**：与全仓现状一致（文案中文硬编码、颜色走 `--al-*` 令牌跟随主题）。若宿主将来上浅色主题，`--al-*` 令牌能跟随，但本插件里若干 `rgba(...)` 字面量（遮罩、错误底、hover 底）不会随主题变。
5. **删除确认窗口 4s**：窗口内误点第二下就会真删（无撤销）。需求允许"二次确认**或**可撤销"，已实现前者；未做撤销栈。
6. **多标签页**：`storage` 事件已让列表失效重算（接线 K14），但**同一时刻打开编辑弹窗的两个标签页**可能互相覆盖（后保存者胜）——未做版本冲突检测。
7. **容量与超长**：正文上限 2000 字/条，条数**无上限**；localStorage 配额（约 5MB）耗尽时保存会失败并给出可见提示（不静默），但不会自动清理。
8. **"上方不足 → 翻转下方"这条分支未在真机上单独观测到**：正常视口下 composer 按钮上方总有 260px 以上空间（走的是上拉分支），短视口下又先被限位接管（真机 F24 实测 `top=35`）。该分支由叶子单测逐条覆盖（C34 翻转、C36 超高面板），真机覆盖的是"限位后仍在视口内"这一可观测结果。
9. **"无内存泄漏"是结构性保证，未做运行时测量**：全部监听成对 add/remove、portal 宿主节点与计时器都在 cleanup 里收回（接线 K5/K7/K8 逐条断言），但**没有**用堆快照或监听器计数在真机上量过。需求 8.6 的"无内存泄漏"按此口径交付。
10. **未覆盖的机器判据**：无。视觉"是否好看到位"、遮罩透明度是否符合审美，属人工判断项。
